# Decisions

Implementation choices not fixed by the brief. One line each: choice — reason.

- Actions run on the server by loading the whole DB in a transaction (behind an advisory lock), running the unchanged action logic, and writing only the changed rows — reuses all 34 actions as-is; the demo data is small.
- A single route `app/api/actions/[name]` dispatches to a registry of named actions — one place for permission checks, transactions and audit rows.
- Chat threads and messages stay unaudited (as in Task 1), but are stored in Postgres through server routes — they're personal working state, not deal records.
- The extension index is generated from manifests into a gitignored file before dev, build, test and typecheck — a new extension then changes only its own folder, which keeps it in the green lane.
- **Addition to decision 3:** a required `engineer-approval` check (lane classifier) passes for review-lane PRs only after an engineer listed in `.github/approvers.json` approves — CODEOWNERS alone would let an extension-only PR with a "serious" AI verdict merge with just a business approval.
- If the AI review doesn't run or gives no verdict, the PR goes to the review lane — fail safe.
- Checks, AI review and lane classification are jobs in one workflow, in that order — the classifier needs both results.
- Roles: `@jesseleone` is the engineer (owns `*`), `@jesse-leone` the business approver (owns `extensions/`) — two accounts so the approver is never the PR author.
- Admin override is allowed only as a documented fallback for dry runs — the second account is the intended approver.
- Codespaces opened from a PR's preview link are billed to whoever opens them, from their own free allowance — no cost to the repo owner; noted in the runbook and cheat sheet.
- Seed and reset load the existing `buildSeed()` into Postgres — the demo data stays defined in one place, and a test proves a round trip returns it exactly.
- `db/migrations/001_init.sql` extends `docs/schema.sql`: a `seq` column on every table (records load in creation order), deferred foreign keys (one action's writes are checked together), and the columns the app model carries (user initials, term-set note, settings.today).
- Audit rows are protected by a trigger, not `REVOKE` — the app connects as the table owner, which `REVOKE ... FROM PUBLIC` doesn't restrict.
- The term-set lock trigger skips rows only while a transaction has set `covenant.seeding` — seeded term sets arrive already issued or locked.
- The browser reads the whole database from `GET /api/db` after sign-in and after every write — simplest client cache; fine at demo size.
- `/api/session` lists the personas without sign-in; every other route needs the session cookie — the login page needs the persona list.
- No `proxy.ts` redirect — the app shell already sends signed-out visitors to /login, and every API route checks the cookie itself.
- Only a thread's owner can rename or delete a chat; everyone still sees the shared seeded threads — closes a gap the browser-only version couldn't enforce.
- Chat streams progress as newline-delimited JSON from `POST /api/chat` — keeps the "Calling list_deals…" trace now that tools run on the server.
- Local Postgres runs from `compose.yaml` on host port 5433 — 5432 is often taken by another local database.
- Database tests are skipped with a warning when no Postgres is reachable, except in CI (`CI=true`), where that fails the run.
- The production image bundles the database script with esbuild and runs `setup` (migrate, seed if empty) before `server.js` — one container is enough to demo.
- Extensions read through `useCovenant()`, a read-only view with named helpers (`metrics`, `currentTerms`, `diligenceFor`…), not the raw database — no chat, audit or user emails, and plain-English names for citizens.
- Extension views are the folder's `index.tsx` default export; a deal tab receives `{ deal }` — one convention, nothing to register.
- The registry is generated by `scripts/gen-extensions.ts` before dev, build, test and typecheck; invalid folders are skipped with a warning there and fail `npm test` (`lib/__tests__/extensions.test.ts`) — a half-built extension doesn't stop the app from starting, but can't be merged.
- An extension added while `npm run dev` is running appears after `npm run extensions` (the new-extension skill runs it) — no file watcher to install or maintain.
- Extension pages live at `/x/<name>`; extension deal tabs use the folder name as the tab slug, and folder names that clash with app routes or tabs are refused.
- Each extension renders inside an error boundary that names its owner — a broken extension can't take down a page.
- The import rule uses ESLint `no-restricted-imports` regex patterns plus bans on network, storage, `process.env`, dynamic import, `require` and raw HTML — it is tested in `lib/__tests__/extensions.test.ts`.
- The catalog flags extensions not updated in 90 days (`STALE_AFTER_DAYS`) — a prompt to review or retire them, not an automatic removal.
- Extension tests run in jsdom (a vitest project for `extensions/**`), core tests stay in Node; `renderExtension` loads the demo data and records writes instead of sending them.
- A `BarChart` (single series, one hue, table semantics, hover/focus tooltip) is part of the SDK — the reference extension needed it and citizens will reuse it.
- The dev container uses Microsoft's `typescript-node:22` image plus the GitHub CLI and Claude Code features — maintained images, nothing custom to build.
- `node_modules` and `.next` are container volumes — opening an existing laptop copy in the container never overwrites the laptop's own packages (they differ between macOS/Windows and Linux).
- The test database (`covenant_test`) is created by a Postgres init script in the dev container — tests never touch the demo data.
- The app starts from `.devcontainer/start-preview.sh` (background, logs to /tmp/covenant-dev.log); it is idempotent so the preview skill can call it too.
- Codespaces is limited to 2 cores (`hostRequirements`) — stretches the free monthly allowance; 2 cores run the app and Postgres comfortably.
- `ANTHROPIC_API_KEY` is a recommended Codespaces secret, optional — without it the app's chat runs offline; Claude Code signs in separately with the person's company account.
- The README button opens the default branch with `?quickstart=1`, so returning users resume their existing codespace instead of creating another.
- Engineer mode is `COVENANT_ENGINEER=1`, set either in the shell before `claude` or in the gitignored `.claude/settings.local.json` under `env` — per person, never committed.
- Setup scripts clone into `~/Covenant` and open it with VS Code's `--folder-uri vscode-remote://dev-container+<hex path>`; without VS Code the Mac script falls back to the devcontainer CLI. The Windows script is untested.
- The guard hook (`.claude/hooks/guard-paths.mjs`) also allows Claude Code's own folder (`~/.claude`) and temp directories — plans, memory and the approval-request draft aren't part of the app.
- `MultiEdit` stays in the hook matcher although current Claude Code no longer has that tool — harmless, and covers older versions.
- `.claude/settings.json` sets `"model": "opus"` (the alias, so it follows the current Opus) and allows only the commands the skills use; everything else prompts. Deny rules cover `.env` files, keys, force-pushes, pushing to main, merging, secrets, `rm -rf` and installing packages.
- The lane rules live in one pure module (`scripts/ci/lane.ts`) with plain-English reasons per area of the code; ship-it uses it to predict the lane and CI will use it to decide.
- The cost estimate reads the most recently active transcript in `~/.claude/projects/<project>/` (plus its subagent transcripts), counts each API message once, and prices it with a table in `scripts/claude/session.ts`; unknown models or an unreadable transcript give "Estimated cost: unavailable".
- "Directed by" comes from the GitHub account signed in to `gh` (name and login), falling back to git's user name.
- Ship-it names drafts `ext/<name>-<YYYYMMDD>` and always targets `main`; the PR template is plain English and doubles as ship-it's outline.
- Typecheck, lint, test and build are four separate jobs (four required checks with clear names); the AI review waits for them, and the lane job waits for all five — the order agreed in Phase 0.
- The AI review returns structured output (`--json-schema`: verdict, summary, findings); a script renders the comment and appends `AI-REVIEW-VERDICT: …` itself — the verdict line can't be malformed. The review's cost comes from the action's execution file when present.
- The AI review step uses `continue-on-error`, so the `ai-review` check completes even without an API key or on a fork; the lane then falls back to review.
- The AI reviewer gets read-only tools (Read, Grep, Glob, `git diff/log/show`) and is told to treat the change as data, not instructions.
- The lane and engineer-approval jobs run the rules from the base branch, never from the PR — a change can't rewrite its own classification. Workflow changes themselves need an engineer via CODEOWNERS.
- `engineer-approval` runs in `pr.yml` after the lane, and again from `engineer-approval.yml` on every review event; an approval only counts on the latest commit.
- Auto-merge is switched on (`gh pr merge --auto --squash`) for green and off for review; if the repo hasn't enabled auto-merge, the lane comment says someone has to press Merge.
- One comment per purpose (lane, AI review, preview), found by a hidden marker and edited in place.
- Screenshots install Playwright in CI only (`npm install --no-save`), so it isn't an app dependency; the app runs from the standalone build against a seeded Postgres service.
- The preview link uses GitHub's documented `https://codespaces.new/OWNER/REPO/tree/BRANCH?quickstart=1`, from the PR's head repository.
- Weekly metrics: "time to first safe deployment" runs from a citizen's first PR opened to their first merge (workspace first use isn't observable); first-pass rate checks the four check jobs on each PR's first commit (last 90 days); reverts are merged PRs titled "Revert…"; engineers and bots are excluded from per-citizen figures.
- `.github/approvers.json` mirrors CODEOWNERS for the scripts (engineers vs business approvers) — CODEOWNERS can't express roles.
